# Spec Delta

## MODIFIED Requirements

### Requirement: Protect invitation secrets and limit attempts
Секрет приглашения SHALL не попадать в серверные журналы, ошибки или последующие ответы. Авторизованные попытки preview и accept SHALL совместно ограничиваться 10 запросами за фиксированное окно 60 секунд на пользователя, общим для экземпляров сервиса; превышение SHALL возвращать 429 с Retry-After. Успешные и неуспешные попытки, включая невалидные тела, SHALL учитываться одинаково. Сбой хранилища лимита SHALL давать 503 без доступа к приглашению.

#### Scenario: Rate limit
- **WHEN** пользователь отправляет одиннадцатый запрос принятия в одном окне
- **THEN** система возвращает 429 без изменения членства или приглашения

#### Scenario: Secret handling
- **WHEN** принятие завершается успехом либо ошибкой
- **THEN** токен отсутствует в журналах, сообщении ошибки и ответе принятия

#### Scenario: Shared preview and accept quota
- **WHEN** один пользователь отправил девять preview и один accept в одном минутном окне, в том числе через разные экземпляры
- **THEN** следующий preview либо accept возвращает 429 с положительным Retry-After; другой пользователь и следующее окно имеют собственный лимит

#### Scenario: Malformed preview and unavailable counter
- **WHEN** авторизованный preview содержит невалидное тело либо хранилище счётчика недоступно
- **THEN** невалидный запрос учитывается до валидации; при сбое счётчика возвращается 503 без раскрытия группы или изменения приглашения

#### Scenario: Preview secret and query reflection
- **WHEN** preview/accept получает секрет в body или ошибочно в query, с JWT либо без него
- **THEN** токен и digest не появляются в application logs или ответах, включая path ошибки; query не используется как источник токена

## ADDED Requirements

### Requirement: Authenticated minimal invitation preview
POST /group-invitations/preview SHALL требовать JWT и возвращать 200 только с name, type и expiresAt действительного приглашения. Членство SHALL не требоваться. Название и тип SHALL отражать текущую группу; expiresAt SHALL быть сроком ссылки. Сведения об участниках, приглашающем, идентификаторах, правах и финансах SHALL отсутствовать. Успешный ответ SHALL иметь Cache-Control: no-store.

#### Scenario: Recipient confirms destination
- **WHEN** авторизованный пользователь вне группы отправляет действительный токен
- **THEN** получает только name группы, type family либо organization и expiresAt в ISO-формате; доступ к деталям группы и финансам не открывается

#### Scenario: Authenticate first
- **WHEN** пользователь отправляет preview без действительного JWT
- **THEN** возвращается 401 без раскрытия приглашения или группы

#### Scenario: Preview by existing member
- **WHEN** владелец или действующий участник предпросматривает действительное приглашение своей группы
- **THEN** возвращается тот же минимальный ответ 200; приглашение остаётся доступно другому получателю, а собственный accept сохраняет 409

### Requirement: Preview validates token and availability
Preview SHALL принимать только JSON body с token в формате секрета приглашения: 43 символа base64url. Пустые/невалидные тела, неизвестные поля и query SHALL отклоняться с 400. Неизвестный, использованный, отозванный, истёкший токен и приглашение удалённой группы SHALL возвращать одинаковый 400 Invalid invitation без сведений о причине. При now >= expiresAt ссылка SHALL быть недействительна.

#### Scenario: Strict preview input
- **WHEN** token отсутствует, равен null, имеет неверный формат, либо запрос содержит лишнее поле/query
- **THEN** возвращается 400 без раскрытия группы, потребления ссылки и создания членства

#### Scenario: Uniform invalid preview
- **WHEN** корректный по формату токен неизвестен, accepted, revoked, expired или связан с удалённой группой
- **THEN** status, message и error одинаковы для всех случаев; идентификаторы, состояние и данные группы отсутствуют

#### Scenario: Exact expiration boundary
- **WHEN** preview выполняется ровно в expiresAt
- **THEN** возвращается общий 400; непосредственно до срока действительная ссылка доступна без продления срока

### Requirement: Preview never accepts or reserves invitation
Preview SHALL не изменять приглашение, членство, события, группу или финансовые данные; SHALL изменяться только счётчик попыток. Повторный preview SHALL не потреблять и не продлевать ссылку. Accept SHALL заново проверять актуальную доступность и сохранять атомарность одноразового вступления. Успешный preview SHALL не гарантировать последующий accept.

#### Scenario: Repeated preview then acceptance
- **WHEN** пользователь дважды предпросматривает ссылку, затем явно принимает её
- **THEN** до accept приглашение pending, членства и новых событий нет, группа и финансы неизменны; accept создаёт ровно одно членство и потребляет ссылку

#### Scenario: Availability changes after preview
- **WHEN** после успешного preview ссылку отозвали, использовал другой получатель, истёк срок или удалена группа
- **THEN** последующий preview и accept возвращают общий 400; прежний preview не предоставляет права вступить

#### Scenario: Concurrent preview and acceptance
- **WHEN** preview конкурирует с принятием ссылки другим пользователем
- **THEN** preview возвращает минимальный ответ для прочитанного действительного состояния либо общий 400; только accept создаёт членство, повторного потребления или аудита от preview нет
