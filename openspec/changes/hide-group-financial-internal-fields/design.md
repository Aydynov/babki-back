# Design

## Context

`AccountsService.responseForBudget` возвращает lean account с mutationVersion и __v; другие сервисы также возвращают версии Mongoose. Сквозной тест этапа 10 воспроизводит проблему. Существующий personalResponse рекурсивно обходит ответы, сохраняя Date/ObjectId и преобразуя Mongoose documents в plain objects.

## Goals / Non-Goals

Goals: одинаковая политика исключения служебных полей на всей границе групповых финансов, включая вложенные ответы; повторное использование существующего обхода.

Non-Goals: менять личный wire format, данные/индексы/арифметику/транзакции, создавать DTO для каждой комбинации или глобальный фильтр всех ответов приложения.

## Decisions

Выделить существующий рекурсивный обход personalResponse в общий omitResponseFields(value, fields). PersonalResponse делегирует ему с прежним набором ключей без изменения поведения. Новый GroupFinancialResponseInterceptor использует тот же helper с набором __v/mutationVersion/lockVersion. Подключить через UseInterceptors к трём финансовым контроллерам: основной, plans, debts. Контроллеры групп/приглашений, личные маршруты и сервисные вызовы не затрагиваются. Это покрывает все HTTP-семейства одной политикой и не удаляет поля из доменных объектов до завершения финансовой транзакции. Отдельные ручные omit в каждом сервисе были бы легко пропускаемы; глобальный interceptor менял бы личный контракт.

Helper не мутирует вход, сохраняет Date/ObjectId, null/undefined, числовые нули/отрицательные/дробные значения. Документ Mongoose переводится через существующий toObject. Unit проверяет вложенные arrays/documents и отсутствие мутаций, HTTP regression проверяет create/PATCH/detail/list для всех семейств и compound repay/cancel. Финансовые ожидания и shared-engine guards остаются прежними.

## Risks / Trade-offs

- Клиент мог использовать служебные поля → документировать удаление как изменение ответа; сохранять все публичные ссылки и денежные поля.
- Общий helper может повлиять на personalResponse → сохранить прежний алгоритм/набор ключей и выполнить личные characterization suites.
- Interceptor действует после завершения транзакции → обход работает только с уже сформированными документами, не делает I/O или lookup; ошибки actor lookup по-прежнему откатываются внутри сервиса.

## Migration Plan

Миграции нет. Проверки и code commit предшествуют sync/archive, архив фиксируется вторым коммитом. Откат возвращает прежнюю выдачу metadata, БД не меняется. Этап 10 остаётся отдельным change и продолжается после этого исправления.
