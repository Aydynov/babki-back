# Proposal

## Why

Этапы 01–09 закрыли отдельные пробелы семейного бюджета, но фронтенду нужна единая проверяемая картина итогового контракта. Нужны сверка исходных §1–10, согласованная документация и сквозной сценарий семьи с разными личными валютами без утечек между бюджетами.

## What Changes

- Добавить `docs/family-budget-contract-audit.md`: матрицу исходный пробел → принятое решение → main spec → реализация → конкретная проверка → документация, с явными ограничениями и результатами.
- Сверить и уточнить существующие документы групп, финансов, общего ядра, fixtures и развёртывания: фактические DTO, pagination, optional/null, идентификаторы, авторство, валюты, ошибки и совместимость.
- Добавить один связный HTTP e2e семьи: приглашение, делегирование, счета/резерв, операции/перевод, план, долг, отчёты, отзыв прав, выход и обезличивание истории. Переиспользовать существующие проверки границ, гонок и миграций.
- Подтвердить общие финансовые механизмы личного и группового бюджетов, актуальность детерминированных fixtures и завершение дорожной карты доказательствами локальных проверок.
- Сохранить цикл: проверка → коммит реализации → архивирование → отдельный коммит архива.

## Capabilities

### New Capabilities

Нет. Change содержит документацию и тесты существующего поведения; `.openspec.yaml` задаёт `skip_specs: true`.

### Modified Capabilities

Нет. Требования уже закреплены в main specs этапов 01–09, включая `budget-ownership`, `group-financial-permissions`, `group-wallet`, `group-transactions`, `account-transfers`, `group-budget-plans`, `group-budget-debts` и `group-invitations`. Новые поведенческие дефекты или противоречия требуют отдельного явно согласованного change до признания аудита полным.

## Impact

Основные изменения: `docs/`, `test/`, при необходимости узкое расширение `test/helpers/groups-test-app.ts`, журнал `docs/family-budget-roadmap.md`. Производственные сервисы, схемы, маршруты, зависимости и main specs не меняются. Новая система контрактов, внешняя публикация Postman, миграция рабочей БД и межбюджетные переводы не входят в объём. Проверки выполняются на временном MongoDB replica set; они не подтверждают состояние развёрнутого API или совместимость ещё не проверенного фронтенда.
