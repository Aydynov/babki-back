# groups Specification

## Purpose

Поддержать независимые семьи и рабочие организации с защищённым управлением жизненным циклом и сохранением личных данных пользователей.

## Requirements

### Requirement: Create independent groups

Система SHALL позволять авторизованному пользователю создавать пространства, атомарно назначая его единственным владельцем и действующим участником. Название SHALL содержать 1–100 символов после trim, необязательное описание — не более 1000. Пространство SHALL не иметь типа и SHALL создаваться без финансовых сущностей.

#### Scenario: Create a group
- **WHEN** пользователь отправляет POST /spaces с name и необязательным description
- **THEN** получает 201, пространство с _id, ownerId, timestamps, своей ролью и permissions; возникает только пространство и членство владельца, без счетов и иных финансовых записей

#### Scenario: Invalid or unauthenticated creation
- **WHEN** запрос не авторизован либо содержит пустое название, type или неизвестное поле
- **THEN** возвращается соответственно 401 либо 400; пространство и членство не создаются

### Requirement: Read only accessible groups

GET /spaces SHALL возвращать только неудалённые пространства с действующим членством пользователя, сохраняя стандартную пагинацию. Недоступное, удалённое или отсутствующее пространство SHALL давать 404. DTO SHALL содержать текущие роль и permissions и SHALL не содержать type.

#### Scenario: Several independent groups
- **WHEN** пользователь состоит в трёх пространствах и запрашивает список
- **THEN** получает все три доступных пространства без чужих и покинутых

#### Scenario: No membership
- **WHEN** посторонний пользователь запрашивает известный ему spaceId
- **THEN** получает 404 без раскрытия пространства

#### Scenario: Empty list is valid
- **WHEN** авторизованный пользователь не имеет действующих пространств
- **THEN** GET /spaces возвращает 200 со стандартной пагинацией, items=[] и total=0

### Requirement: Owner manages group metadata

Только текущий владелец SHALL изменять name и description пространства. Пустое описание SHALL очищать его; пустой PATCH SHALL давать 400. Участник без роли владельца SHALL получать 403.

#### Scenario: Update group
- **WHEN** владелец меняет название или очищает описание
- **THEN** пространство обновляется с сохранением идентификатора и членства, без поля type

#### Scenario: Prevent privilege injection
- **WHEN** PATCH содержит ownerId, type, статус или другое недопустимое поле
- **THEN** возвращается 400 без изменений

### Requirement: Delete without destroying history

Только владелец SHALL удалять пространство. Удаление, завершение действующих членств и отзыв ожидающих приглашений SHALL быть атомарными. Пространство SHALL стать недоступным всем; его идентичность, финансы, приглашения и история членства SHALL сохраняться. Публичного восстановления и доступа к архиву SHALL не быть.

#### Scenario: Owner deletes group
- **WHEN** владелец удаляет пространство
- **THEN** получает 204, пространство исчезает из доступных списков, членства завершаются, pending invitations отзываются; финансовая история сохраняется, другие пространства не меняются

#### Scenario: Member attempts deletion
- **WHEN** обычный участник удаляет пространство
- **THEN** получает 403 без изменений пространства, членств или приглашений

#### Scenario: Atomic deletion failure
- **WHEN** завершение членств или отзыв приглашений завершается ошибкой
- **THEN** вся операция откатывается, пространство остаётся доступным в прежнем состоянии

### Requirement: Users may remain without spaces

Регистрация SHALL создавать только аккаунт пользователя, без пространства, членства или финансов. Пользователь SHALL иметь возможность входить, читать и менять профиль, создавать пространство и принимать приглашение при нуле пространств. Создание собственного пространства SHALL не быть условием вступления в существующее.

#### Scenario: Register without financial setup
- **WHEN** пользователь регистрируется с корректными данными без currency
- **THEN** получает действующую авторизацию и профиль без финансовых настроек; список пространств пуст, финансовые сущности отсутствуют

#### Scenario: Join first space
- **WHEN** пользователь без пространств принимает действующее приглашение
- **THEN** получает доступ к существующему пространству без создания собственного

#### Scenario: Remain after losing last space
- **WHEN** пользователь выходит из последнего пространства, исключён или последнее доступное пространство удалено
- **THEN** аккаунт остаётся активным, список пространств пуст и доступны создание пространства и принятие приглашения
