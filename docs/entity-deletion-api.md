# Удаление и архивирование сущностей

Все маршруты требуют JWT. Успешный `DELETE` возвращает `204` без тела. Отсутствующая либо уже физически/логически удалённая цель возвращает `404`; запрет из-за исторической зависимости — `409`.

| Сущность                      | DELETE                                                                                             | Связанные данные                                                                                                | Архивирование                                                                              |
| ----------------------------- | -------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| Личный или групповой счёт     | Только при нулевом начальном остатке и полном отсутствии операций по `accountId`/`sourceAccountId` | Для пустого счёта каскадно удаляются только snapshots                                                           | `POST /accounts/:id/archive` для личного счёта; новые операции запрещены, история читается |
| Личная или групповая операция | Soft delete с `deletedAt/deletedBy`; повтор — `404`                                                | Балансы затронутых счетов компенсируются ровно один раз; история продолжает блокировать удаление справочников   | Не применяется                                                                             |
| Категория расходов            | Физически удаляется только без операций, лимитов и планов                                          | Проверка и удаление сериализованы с конкурентными назначениями                                                  | `PATCH .../expense-categories/:id` с `isArchived: true`; новые назначения запрещены        |
| Лимит расходов                | Физическое удаление leaf-записи                                                                    | Категория и операции не меняются                                                                                | Не применяется                                                                             |
| План                          | Только активный план без созданного расхода                                                        | Закрытый план и origin-расход сохраняются                                                                       | `POST /plans/:id/archive`; архивные планы исключены из списка                              |
| Долг                          | Только долг без погашений и origin-дохода                                                          | Погашения и доход сохраняются                                                                                   | `POST /debts/:id/archive`; архивные долги исключены из списка                              |
| Группа                        | Root soft delete                                                                                   | Active memberships завершаются с `group_deleted`, pending invitations отзываются; финансы и события сохраняются | Публичного восстановления и доступа к архиву нет                                           |
| Пользователь                  | Необратимая staged-очистка после step-up                                                           | Личный бюджет и auth-секреты удаляются; групповая история остаётся со ссылкой на PII-free tombstone             | Не применяется                                                                             |

## Удаление пользователя

`POST /auth/account-deletion` принимает:

```json
{
  "password": "current password",
  "secondFactorCode": "012345"
}
```

`secondFactorCode` обязателен, если у пользователя включён TOTP. Владелец неудалённой группы получает `409` до передачи владения либо удаления группы. Принятый запрос возвращает `202`, сразу переводит пользователя в `deletion_pending`, увеличивает `authVersion` и блокирует старые JWT и новый login.

Фоновая очистка необратима. Она оставляет только стабильный `_id`, `status: deleted`, `deletedAt` и технические timestamps пользователя. Имя, email, password hash, 2FA, challenges, IP и User-Agent удаляются; групповые операции, memberships, invitations и membership events не переписываются и не удаляются.

Worker запускается командой `npm run user-deletion:work`. Команда обрабатывает доступные этапы до опустошения очереди; lease не позволяет двум workers выполнять один этап одновременно.
